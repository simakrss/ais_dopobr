# АИС Допобразование Web

Первый web-MVP системы управления учебным центром на основе структуры книги `АИС Допобразование.xlsb`.

## Запуск

Для полного режима с сохранением фотографий на диск запустите локальный сервер из папки `web-ais`:

```powershell
node app-server.js
```

После запуска откройте `http://localhost:8080`. Фотографии слушателей сохраняются в `storage/photos` и удаляются из этого же файлового хранилища при удалении фото или карточки слушателя.

Для работы используйте HTTP-сервер: реестры `data/*.js` выдаются только после входа в систему.

## Пользователи и роли

Учётные записи и PBKDF2-хеши паролей хранятся в защищённом `storage/users.json` локально или вне `public_html` на хостинге. Сессии используют cookie `HttpOnly` и `SameSite=Strict`.

При первичном запуске без файла пользователей задайте пароль администратора длиной не менее 12 символов в переменной `AIS_INITIAL_ADMIN_PASSWORD`. Пароль менеджера при создании по умолчанию — `123`.

- администратор имеет доступ ко всем разделам и управлению пользователями;
- менеджер не видит разделы «Настройки» и «Админка» и получает отказ от соответствующего API;
- email, телефон и пароль пользователь меняет в личном кабинете;
- логин текущей учётной записи записывается в поле «Ответственный» и журнал действий.

Журнал изменений хранится на сервере в защищённом `audit-log.jsonl`. Администратор видит общую историю всех пользователей, изменения полей в формате «было/стало», IP и клиент, может фильтровать записи по каждому параметру и скачивать отфильтрованный CSV. Пароли, токены и другие секреты в журнале маскируются.

## Размещение на виртуальном хостинге Timeweb

На виртуальном хостинге API обслуживает `gateway.php`: для каждого запроса он запускает Node.js как короткую консольную задачу через `server-cli.js`. Исполняемый runtime, серверные исходники, пользователи и защищённые данные должны находиться вне `public_html`, а `AIS_APP_ROOT` указывать на каталог web-приложения. `.htaccess` направляет API и защищённые реестры в PHP-шлюз и запрещает прямой доступ к `storage`; вход выполняется через единую форму авторизации приложения.

Такой режим поддерживает WebDAV, IMAP/SMTP, импорт XLSB, получение заявок WooCommerce, формирование DOCX и автономное OCR как короткую Python-задачу. PDF через ONLYOFFICE требует отдельного постоянно работающего сервера; виртуальный хостинг Timeweb не позволяет запускать ONLYOFFICE как системную службу.

## Конвертация документов в PDF

PDF формируется серверным ONLYOFFICE Docs Community, без Microsoft Word и LibreOffice. Для локального запуска задайте тот же JWT-секрет, который хранится в `storage/server-settings.json` в параметре `documentConverterJwtSecret`, и запустите сервис:

```powershell
$env:ONLYOFFICE_JWT_SECRET = "<секрет>"
docker compose -f docker-compose.onlyoffice.yml up -d
```

Для публикации задайте приложению переменные окружения:

- `ONLYOFFICE_CONVERTER_URL` — внутренний адрес ONLYOFFICE Docs, например `http://127.0.0.1:8082`;
- `ONLYOFFICE_SOURCE_URL` — адрес приложения, доступный контейнеру, например `https://lms.edu-plus.ru`;
- `ONLYOFFICE_JWT_SECRET` — общий случайный секрет приложения и ONLYOFFICE.

Порт ONLYOFFICE в Compose привязан к `127.0.0.1` и не публикуется напрямую в интернет. Временные DOCX доступны конвертеру по одноразовым случайным ссылкам не более пяти минут.

## Автономное распознавание документов

На вкладке «Документы» карточки слушателя доступно локальное распознавание паспорта, ИНН, СНИЛС и диплома. Система анализирует файлы `JPG`, `PNG` и `PDF` из папки документов слушателя, показывает найденные реквизиты для проверки и только после подтверждения переносит выбранные значения в карточку.

OCR выполняется контейнером `ais-ocr` на базе Tesseract с языками `rus+eng`. Контейнер запускается той же командой Compose, что и ONLYOFFICE:

Вместе с реквизитами OCR ищет лицо на всех страницах прикреплённых документов. В окне результата можно выбрать найденный портрет или открыть любой файл, перейти на нужную страницу и выделить произвольную область. Фото сохраняется только после явного выбора пользователем.

```powershell
$env:ONLYOFFICE_JWT_SECRET = "<секрет>"
docker compose -f docker-compose.onlyoffice.yml up -d --build
```

По умолчанию локальный OCR доступен приложению на `http://127.0.0.1:8083`. Для отдельного постоянно работающего сервера адрес можно изменить переменной окружения `OCR_SERVICE_URL`. Порт привязан только к localhost.

На виртуальном хостинге PHP-шлюз задаёт `AIS_OCR_CLI=1` и запускает `services/ocr/server.py --recognize-stdin` через системный Python. Переносимый Tesseract, библиотеки и языковые модели находятся в закрытом каталоге `lms-runtime/app/services/ocr/runtime`; файлы для распознавания загружаются через WebDAV, обрабатываются во временной папке хостинга и удаляются после завершения запроса.

Данные стартового набора находятся в `data/seed.js`. После первого изменения приложение хранит рабочую копию в `localStorage` браузера. В админке есть экспорт/импорт JSON, сброс к стартовым данным и журнал действий.

## Стандарт вкладок

Все наборы вкладок подключаются через общий механизм `getOrderedTabs` и атрибуты `data-orderable-tabs` / `data-orderable-tab`. Он обеспечивает перетаскивание, сохранение порядка в `localStorage`, клавиатурную навигацию и восстановление исходного порядка через контекстное меню. Новые вкладки следует добавлять только через этот механизм.

## Что уже есть

- панель управления учебным центром;
- разделы: слушатели, договоры, программы, учебные планы, вебинары, финансы, запасы;
- вкладочная карточка слушателя с фото, документами, коммуникациями, доходами, расходами, приказами, СДО, итогами и отзывом;
- админка: пользователи, роли, справочники, импорт/экспорт, журнал, карта Excel-книги;
- поиск, фильтры, сортировка, карточки редактирования, удаление и восстановление стартовых данных;
- адаптивный интерфейс для рабочего стола и планшета.

## Следующий этап

Для промышленной версии нужно заменить локальное хранилище на серверную БД и выполнить полный импорт из `АИС Допобразование.xlsb`:

1. PostgreSQL или MS SQL Server для основных таблиц.
2. Backend API: авторизация, роли, аудит, документы, платежи, интеграции.
3. Импорт из Excel: листы `База`, `Реестр договоров`, `Реестр программ`, `Учебные планы`, `Вебинары`, `Прямые затраты`, `Общие затраты`, `Запасы`, `Настройки`.
4. Перенос бизнес-логики из VBA-модулей `Main`, `КарточкаСлушателя`, `КарточкаКонтрагента`, `ИмпортЗаявок`, `Настройки`, `WhatsApp_BOT`, `FTP/JupiterSync`.
5. Формирование документов и отчетов на сервере вместо макросов Excel.
