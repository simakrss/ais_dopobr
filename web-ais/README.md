# АИС Допобразование Web

Первый web-MVP системы управления учебным центром на основе структуры книги `АИС Допобразование.xlsb`.

## Запуск

### Запуск без Codex для всей локальной сети

Дважды щёлкните корневой файл `ЗАПУСТИТЬ АИС.bat` или файл `ЗАПУСТИТЬ АИС В ЛОКАЛЬНОЙ СЕТИ.cmd` в папке `web-ais`. При первом запуске Windows запросит права администратора, установит настоящую службу `АИС Допобразование` (`AisDopobrWeb`) с автоматическим отложенным запуском, запустит её и зарегистрирует иконку управления в системном трее. В дальнейшем тот же файл только запускает уже установленную службу, дожидается готовности `http://127.0.0.1:8081/` и открывает сайт в браузере. Закрытие окна запуска не останавливает АИС, а повторный запуск не создаёт вторую копию серверов.

Служба управляет отдельным интерактивным рабочим процессом текущего пользователя. Это необходимо, чтобы сохранились синхронизация XLSB через Excel, диалоги выбора файлов и открытие локальных документов: из изолированного сеанса Windows-службы эти окна не видны. После выхода из учётной записи служба остаётся включённой, а рабочий процесс автоматически возобновится при следующем входе. Для непрерывной доступности в локальной сети учётная запись сервера должна оставаться в системе.

При первом запуске Windows также может попросить разрешить создание правила брандмауэра для TCP-порта 8081. Правило разрешает подключения только из локальной подсети; API, OCR и OnlyOffice остаются доступны только на этом компьютере.

Скрипт автоматически:

- получает обновления текущей ветки из GitHub (только fast-forward, без автоматической отправки локальных коммитов);
- публикует безопасный набор файлов на `https://edu-plus.ru/lms/` по FTP и проверяет полный размер каждого файла;
- сохраняет незакоммиченные отслеживаемые изменения в `git stash`, чтобы они не потерялись и не попали на сайт;
- при доступном Docker поднимает OCR и OnlyOffice, а при временно недоступном Docker запускает основную АИС без них;
- запускает внутренний API на `127.0.0.1:19081`;
- запускает сетевой адрес приложения на порту `8081`;
- проверяет работоспособность локального адреса и автоматически перезапускается средствами Windows при аварийном завершении;
- сохраняет журналы запуска и серверов в `tmp/lan-system`.

FTP-реквизиты и каталог публикации читаются из ярлыка `lms на vh458.timeweb.ru.lnk` и не записываются в исходный код или журнал. Приватные шаблоны договоров с печатями и подписями исключены из публикации. Если GitHub или FTP временно недоступны, локальная АИС всё равно запускается на последней доступной версии.

В меню иконки АИС в трее доступны запуск, остановка и перезапуск службы, открытие локального сайта, папки журналов и пункта «Окно терминала запуска». Этот пункт открывает обычное окно PowerShell с последними строками живого журнала службы; закрытие окна просмотра не останавливает АИС. Цвет иконки показывает состояние: система готова, запускается, остановлена или требует внимания.

Для остановки также можно использовать любой файл `ОСТАНОВИТЬ АИС.cmd`. Остановка и перезапуск службы не завершают контейнеры Docker: OCR и OnlyOffice остаются поднятыми, поэтому следующий запуск проходит быстрее. Компьютер-сервер должен оставаться включённым, а его локальный IP-адрес не должен меняться; рекомендуется закрепить адрес в настройках роутера.

Те же операции доступны из PowerShell в папке `web-ais`:

```powershell
& .\scripts\control-ais-service.ps1 -Action Start -InstallIfMissing -OpenBrowser -ShowTray
& .\scripts\control-ais-service.ps1 -Action Stop
& .\scripts\control-ais-service.ps1 -Action Restart
& .\scripts\control-ais-service.ps1 -Action Status
& .\scripts\control-ais-service.ps1 -Action Log
```

Удалить только регистрацию службы и автозапуск иконки, сохранив данные АИС, журналы и Docker-контейнеры, можно командой:

```powershell
& .\scripts\control-ais-service.ps1 -Action Uninstall
```

Все компьютеры локальной сети и опубликованная версия `https://edu-plus.ru/lms/` работают с одной общей MySQL-базой. Ревизия хранится в `ais_shared_state_meta`, а карточки, справочники и настройки — отдельными строками в `ais_shared_state_entries`, поэтому изменение одной карточки не перезаписывает всю базу. Локальный сервер проверяет ревизию раз в секунду и хранит проверенный снимок; опубликованный шлюз хранит такой же ревизионный снимок между запросами. Первое открытие получает готовый снимок, а полные данные MySQL перечитываются только после изменения числовой ревизии. Изменения передаются как патчи отдельных записей: сервер атомарно объединяет независимые правки, даже если два компьютера начали работу с разных ревизий. Открытая для редактирования запись получает распределённую блокировку с автоматическим продлением; блокировки хранятся в `ais_record_locks`, обновляются каждую секунду и автоматически истекают через 30 секунд при аварийном отключении клиента.

При недоступном интернете локальный сервер продолжает отдавать последнюю полную копию базы, принимает изменения и сохраняет их в `storage/shared-application-state-pending.json`. Блокировки внутри локальной сети временно переключаются на локальное хранилище. После восстановления MySQL очередь автоматически выгружается по порядку и сливается с актуальной ревизией; индикатор в шапке показывает автономный режим и количество ожидающих изменений. Браузер дополнительно хранит небольшой патч незавершённой отправки, чтобы повторить её после перезагрузки страницы. Старый архив WebDAV используется только для первоначального переноса данных и резервной совместимости. Подключение настраивается в разделе «Админка → Подключение к базе»: можно использовать MySQL базы заявок или указать отдельные сервер, порт, базу, пользователя и пароль, затем выполнить встроенную проверку. Переменная `AIS_RECORD_LOCKS_MYSQL_CONNECTION_STRING` имеет приоритет над настройками интерфейса.

Для полного режима с сохранением фотографий на диск запустите локальный сервер из папки `web-ais`:

```powershell
node app-server.js
```

После запуска откройте `http://localhost:8080`. Фотографии слушателей сохраняются в `storage/photos` и удаляются из этого же файлового хранилища при удалении фото или карточки слушателя.

Для работы используйте HTTP-сервер: реестры `data/*.js` выдаются только после входа в систему.

## Пользователи и роли

Учётные записи и PBKDF2-хеши паролей хранятся в защищённом `storage/users.json` локально или вне `public_html` на хостинге. Сессии используют cookie `HttpOnly` и `SameSite=Strict`.

При первичном запуске без файла пользователей задайте пароль администратора длиной не менее 12 символов в переменной `AIS_INITIAL_ADMIN_PASSWORD`. Пароль менеджера при создании по умолчанию — `123`.

- администратор имеет доступ ко всем разделам и управлению пользователями;
- менеджер не видит разделы «Настройки» и «Админка» и получает отказ от соответствующего API;
- email, телефон и пароль пользователь меняет в личном кабинете;
- логин текущей учётной записи записывается в поле «Ответственный» и журнал действий.

Журнал изменений хранится на сервере в защищённом `audit-log.jsonl`. Администратор видит общую историю всех пользователей, изменения полей в формате «было/стало», IP и клиент, может фильтровать записи по каждому параметру и скачивать отфильтрованный CSV. Пароли, токены и другие секреты в журнале маскируются.

## Размещение на виртуальном хостинге Timeweb

На виртуальном хостинге API обслуживает `gateway.php`: для каждого запроса он запускает Node.js как короткую консольную задачу через `server-cli.js`. Исполняемый runtime, серверные исходники, пользователи и защищённые данные должны находиться вне `public_html`, а `AIS_APP_ROOT` указывать на каталог web-приложения. `.htaccess` направляет API и защищённые реестры в PHP-шлюз и запрещает прямой доступ к `storage`; вход выполняется через единую форму авторизации приложения.

Такой режим поддерживает WebDAV, IMAP/SMTP, импорт XLSB, получение заявок WooCommerce, формирование DOCX и автономное OCR как короткую Python-задачу. Высококачественный PDF формируется LibreOffice на локальном сервере и передаётся интернет-версии через защищённый туннель; на самом виртуальном хостинге этот конвертер не запускается.

## Туннель к локальным сервисам

Для использования OCR, редактора ONLYOFFICE и LibreOffice-экспорта на этом компьютере при работе через `https://edu-plus.ru/lms/` запустите:

```powershell
& .\scripts\start-remote-services.ps1
```

Сценарий поддерживает контейнеры OCR и ONLYOFFICE, Node-сервер на внутреннем порту `19081`, локальный адрес приложения `http://127.0.0.1:8081` и Cloudflare Tunnel. Текущий адрес туннеля автоматически записывается в защищённый `storage/tunnel-runtime.json` на сайте. Через туннель передаются только распознавание и формирование документов, включая подтверждение предварительного просмотра; PHP-шлюз сначала проверяет пользовательскую сессию и добавляет отдельный случайный секрет. Прямые запросы к закрытым API туннеля без секрета возвращают `404`.

При открытии интернет-версии браузер сначала проверяет OCR, LibreOffice и редактор ONLYOFFICE на `http://127.0.0.1:8081`. Доступность формирования PDF определяется именно по высококачественному LibreOffice-конвертеру, а доступность редактирования — отдельно по ONLYOFFICE. Если локальная проверка не пройдена, запрос остаётся на `edu-plus.ru/lms` и PHP-шлюз использует защищённый туннель. Локальный межпроцессный ключ создаётся автоматически; удалённому сайту разрешены только API распознавания и формирования документов, причём только через loopback-интерфейс.

Локальные файлы `web-ais/.runtime/*`, включая `cloudflared`, адрес и секрет, не добавляются в Git. Для постоянного промышленного адреса следует заменить Quick Tunnel на именованный Cloudflare Tunnel; остальная схема PHP-шлюза при этом не меняется.

## Конвертация документов в PDF

PDF формируется локальным LibreOffice Writer со сжатием изображений без потерь, без уменьшения разрешения и со встраиванием шрифтов. На Windows автоматически ищется `soffice.com` из обычной установки LibreOffice; на Linux нужен исполняемый `libreoffice` или `soffice` в `PATH`. Нестандартный путь задаётся в `AIS_LIBREOFFICE_BINARY`.

При ошибке LibreOffice система не переключается на растрирующую PDF-конвертацию: запрос завершается ошибкой, чтобы не выдать документ с ухудшенным качеством. ONLYOFFICE остаётся нужен для браузерного редактора. Для локального запуска редактора задайте тот же JWT-секрет, который хранится в `storage/server-settings.json` в параметре `documentConverterJwtSecret`, и запустите сервис:

```powershell
$env:ONLYOFFICE_JWT_SECRET = "<секрет>"
docker compose -f docker-compose.onlyoffice.yml up -d
```

Для публикации задайте приложению переменные окружения:

- `ONLYOFFICE_CONVERTER_URL` — внутренний адрес ONLYOFFICE Docs, например `http://127.0.0.1:8082`;
- `ONLYOFFICE_SOURCE_URL` — адрес приложения, доступный контейнеру, например `https://lms.edu-plus.ru`;
- `ONLYOFFICE_JWT_SECRET` — общий случайный секрет приложения и ONLYOFFICE.

Порт ONLYOFFICE в Compose привязан к `127.0.0.1` и не публикуется напрямую в интернет. Временные DOCX доступны конвертеру по одноразовым случайным ссылкам не более пяти минут.

## Автономное распознавание документов

На вкладке «Документы» карточки слушателя доступно локальное распознавание паспорта, ИНН, СНИЛС и диплома. Система анализирует файлы `JPG`, `PNG` и `PDF` из папки документов слушателя, показывает найденные реквизиты для проверки и только после подтверждения переносит выбранные значения в карточку.

OCR выполняется контейнером `ais-ocr` на базе Tesseract с языками `rus+eng`. Контейнер запускается той же командой Compose, что и ONLYOFFICE:

Вместе с реквизитами OCR ищет лицо на всех страницах прикреплённых документов. В окне результата можно выбрать найденный портрет или открыть любой файл, перейти на нужную страницу и выделить произвольную область. Фото сохраняется только после явного выбора пользователем.

```powershell
$env:ONLYOFFICE_JWT_SECRET = "<секрет>"
docker compose -f docker-compose.onlyoffice.yml up -d --build
```

По умолчанию локальный OCR доступен приложению на `http://127.0.0.1:8083`. Для отдельного постоянно работающего сервера адрес можно изменить переменной окружения `OCR_SERVICE_URL`. Порт привязан только к localhost.

На виртуальном хостинге PHP-шлюз задаёт `AIS_OCR_CLI=1` и запускает `services/ocr/server.py --recognize-stdin` через системный Python. Переносимый Tesseract, библиотеки и языковые модели находятся в закрытом каталоге `lms-runtime/app/services/ocr/runtime`; файлы для распознавания загружаются через WebDAV, обрабатываются во временной папке хостинга и удаляются после завершения запроса.

Данные стартового набора находятся в `data/seed.js` и используются только при создании пустой общей базы. Рабочая база хранится на сервере/WebDAV; `localStorage` браузера содержит лишь аварийную копию для просмотра при временной потере связи и не считается источником данных. В админке есть экспорт/импорт JSON, сброс к стартовым данным и журнал действий.

## Стандарт вкладок

Все наборы вкладок подключаются через общий механизм `getOrderedTabs` и атрибуты `data-orderable-tabs` / `data-orderable-tab`. Он обеспечивает перетаскивание, сохранение порядка в `localStorage`, клавиатурную навигацию и восстановление исходного порядка через контекстное меню. Новые вкладки следует добавлять только через этот механизм.

## Что уже есть

- панель управления учебным центром;
- разделы: слушатели, договоры, программы, учебные планы, вебинары, финансы, запасы;
- вкладочная карточка слушателя с фото, документами, коммуникациями, доходами, расходами, приказами, СДО, итогами и отзывом;
- админка: пользователи, роли, справочники, импорт/экспорт, журнал, карта Excel-книги;
- поиск, фильтры, сортировка, карточки редактирования, удаление и восстановление стартовых данных;
- адаптивный интерфейс для рабочего стола и планшета.

## Следующий этап

При дальнейшем росте объёма данных общую JSON-базу можно заменить на PostgreSQL или MS SQL Server без изменения пользовательского интерфейса:

1. PostgreSQL или MS SQL Server для основных таблиц.
2. Перенос существующего API общей базы на нормализованные таблицы с транзакциями.
3. Импорт из Excel: листы `База`, `Реестр договоров`, `Реестр программ`, `Учебные планы`, `Вебинары`, `Прямые затраты`, `Общие затраты`, `Запасы`, `Настройки`.
4. Перенос бизнес-логики из VBA-модулей `Main`, `КарточкаСлушателя`, `КарточкаКонтрагента`, `ИмпортЗаявок`, `Настройки`, `WhatsApp_BOT`, `FTP/JupiterSync`.
5. Формирование документов и отчетов на сервере вместо макросов Excel.
