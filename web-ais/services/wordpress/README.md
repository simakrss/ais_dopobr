# Генератор образовательных программ

Генератор создаёт черновик лендинга из опубликованной программы edu-plus.ru и виртуальный товар WooCommerce на zifra-plus.ru. Поддерживаются ПРО, ДОП, КПК и ППП. Только для ПРО ссылка встречи SberJazz вводится вручную в параметрах окна «Создать на сайте»; аккаунт/API Jazz не требуется. ДОП, КПК и ППП не создают скачиваемый файл и не требуют даты/времени вебинара или ссылки подключения.

## Установка (требует отдельного разрешения владельца сайтов)

Служебный MU-модуль не включается обычной публикацией АИС. После согласования и коммита:

```powershell
& .\web-ais\scripts\deploy-lms.ps1 -ProgramSites
```

Сценарий использует существующий локальный FTP-профиль через штатный механизм публикации. Он устанавливает только `wp-content/mu-plugins/ais-program-generator.php` двух указанных сайтов, генерирует два независимых ключа и сохраняет их вне `public_html`. Настройки WordPress и существующие страницы/товары не изменяются. Повторная установка сохраняет ключи, несовпадение останавливает установку. Частично установленный модуль без ключа закрыт для подписанных запросов; повторный запуск завершает установку.

- WordPress: `/edu-plus.ru/ais-program-site.key`, `/zifra-plus.ru/ais-program-site.key`.
- Сервер АИС: `/edu-plus.ru/lms-runtime/data/program-site-keys.json`.
- Локальная АИС: `web-ais/storage/program-site-keys.json` (исключён из Git).
- Временные локальные файлы ключей находятся только в игнорируемой `.runtime/program-sites/`.

Не помещайте ключи и пароли WordPress в Git, браузерные настройки или HTML. Административные пароли сайтов генератор не хранит. При утрате доверия к машине сначала отзовите её доступ, затем согласованно замените соответствующие ключи на обеих сторонах.

## Работа

1. В карточке программы заполнить вид, название, часы, стоимость, срок и новый свободный код лендинга. Остальные параметры находятся в окне «Создать на сайте». Для ПРО дополнительно нужны дата, время по Москве и полная ссылка SberJazz. Описание и автор берутся из обязательного прототипа, а не из старых полей АИС. Для длинного названия программы указать короткое название товара (до 128 символов). Для ДОП/ПРО требуется английское название, для КПК/ППП — учебный план. Дата в образцах для курсов по умолчанию текущая (Москва), при необходимости задаётся отдельно; она не меняет сроки обучения слушателей.
2. «Создать на сайте» сохраняет карточку и открывает мастер. Выбрать опубликованный прототип; поиск выполняется только по названию. У дубликата исходная программа запоминается в `sitePrototype` и выбирается по ID/коду лендинга, даже если код копии уже изменён. Явный выбор сохраняется в `siteTemplateId` и имеет приоритет. Отсутствующий прототип нельзя заменить случайным первым результатом.
3. «Подготовить черновики»: копируются ACF-поля, вложенные повторители, описание программы, автор, изображения и публичные рубрики прототипа. Отзывы в `blok_opisaniya_kursa` и полях `review`/`otzyv` берутся непосредственно из исходного лендинга: цитаты, фотографии и ссылки не заменяются. Обновляются название, цена одного предложения, часы, дата, учебный план и ссылки регистрации. Исходный прототип не меняется. Перед публикацией повторно проверяется снимок прототипа; его изменение требует новой подготовки.
4. Автоматически формируются образцы из настроек конструктора: «Сертификат ПРО», «Сертификат ДОП», «Удостоверение о повышении квалификации» или «Диплом о переподготовке». Для сертификатов — RU/EN, для удостоверения/диплома — основной документ и все страницы приложения (3–8 страниц). Используются только данные программы, идентичность ОБРАЗЕЦ/SAMPLE и водяной знак; слушатели и счётчики выдачи не изменяются. Публично загружаются JPEG, не исходные DOCX/PDF. В локальном режиме шаблоны читаются с локального диска; серверная генерация может использовать существующий локальный шлюз PDF/OCR.
5. Войти в WordPress и проверить черновики и все ссылки на образцы. Отзывы, фотографии и неизменённые дополнительные блоки могут относиться к прототипу. Изменения собственных черновиков в WordPress сохраняются при повторе с теми же параметрами; новая подготовка изменённых параметров заменяет их содержимое.
6. Подтвердить проверку и опубликовать. Отображаются результат, ID товара/лендинга, ссылки и промосообщение, сохраняемые в карточке АИС. Товар перенаправляет на `/other_course/<код>/` для ПРО/ДОП, `/courses-pk/<код>/` для КПК, `/courses-pp/<код>/` для ППП. Для КПК/ППП предлагаются прототипы соответствующего раздела; для ДОП доступны все три раздела. Для ПРО подключение доступно через штатную ссылку скачивания заказа WooCommerce, только после проверки разрешения.

Файл подключения HTML хранится в приватной папке `ais-webinar-files/<идентификатор>/connection.html` вне корня сайта; он регистрируется как скачиваемый файл товара. Модуль перенаправляет авторизованное скачивание на SberJazz. Общедоступное правило `?download_file=ID* → Jazz` намеренно не создаётся: оно обошло бы проверку заказа. Другие товары и скачивания не затрагиваются.

Если прервалась связь, повторить действие с теми же параметрами. Программа имеет постоянный ключ, операции защищены блокировкой базы WordPress; повторный запуск не создаёт новые копии. Несовпадение версии программы запрещает публикацию до новой подготовки. Опубликованные объекты с изменёнными параметрами автоматически не перезаписываются.

## Синхронизация существующих программ (модуль 1.3.2)

Вкладка «Сайт» содержит ссылки на лендинг и административную карточку товара (обычный адрес товара может перенаправлять обратно на лендинг). Кнопка «Синхронизировать с сайтом» сохраняет карточку АИС и открывает проверку перед обновлением. Запись доступна администратору; получение ссылок — авторизованным пользователям.

Лендинг определяется по числовому ID из XLSB либо точному коду страницы; при отсутствии кода используются ранее созданный лендинг или ссылка edu-plus.ru. Товары определяются только по ссылкам `add-to-cart` в его ценовых блоках. Для нескольких вариантов предлагается выбор; единственное совпадение часов или ранее подтверждённый товар выбирается предварительно. На общем лендинге обновляется только выбранный ценовой блок (и заголовочная цена, если это первый блок). Название и заполненные общие сведения относятся ко всему лендингу — это явно указано перед подтверждением.

Обновляются названия, текущая/старая цена и скидка, часы, заполненные срок, форма и начало. Описание и автор сохраняются на сайте: устаревшие скрытые значения АИС их не перезаписывают. Текущая цена магазина применяется сразу, прежнее расписание скидки сбрасывается. Адреса, статусы публикации, отзывы, картинки, образцы документов, учебные планы на сайте, файлы подключения и редиректы не меняются. Для обновления не нужны новые образцы или встреча Jazz. Старые программы не присваиваются генератору и не дублируются.

Кнопки взаимоисключающие: подтверждённый лендинг включает синхронизацию и отключает создание, подтверждённое отсутствие — наоборот. Ошибка связи/ACF/неоднозначный код не означает отсутствия: обе кнопки блокируются. Ошибка магазина не отменяет факт наличия лендинга. Собственные незавершённые черновики открываются кнопкой «Продолжить публикацию». Только read-only `resolve` допускает ещё не сохранённые код/промоссылку; все записи в сайты используют сохранённую общую базу. Изменение адреса отменяет актуальность предыдущей проверки.

Проверяются свежие данные общей базы, версии обеих страниц и структура ценового блока; запись повторно проверяет снимок под блокировкой ID страницы. Атомарной транзакции между двумя сайтами нет: при частичном выполнении сообщение указывает обновлённую сторону. «Обновить проверку» и повторное подтверждение завершают операцию без создания копий. Изменение данных после предварительного просмотра требует новой проверки.

Реализация использует штатные [ACF update_field](https://www.advancedcustomfields.com/resources/update_field/) и [WooCommerce CRUD](https://developer.woocommerce.com/docs/best-practices/data-management/crud-objects/), не прямую запись метаданных цен.

## Ограничения первого этапа

Создание самой встречи, изменение четырёх вебинаров главной страницы, настройка списка получателей, согласование со спикером, рекламная рассылка, тестовая оплата и обновление приказа о наборе выполняются отдельно. Для вариантов одной программы существующий код лендинга в карточке сохраняется, но создание новой страницы по занятому адресу запрещено: существующая страница не должна быть молча заменена. Изменения шаблона, формул, названия, параметров или учебного плана требуют повторной подготовки образцов. Публикация проверяет принадлежность и наличие всех файлов, включая страницы приложения в галерее.

Перед первым реальным запуском после установки проверить `/api/program-sites/health` под администратором АИС (без учётной записи — 401), затем прототип, собственные черновики и публикацию на согласованной тестовой программе. До этого нельзя считать интеграцию проверенной на рабочих сайтах.

## Проверки без рабочих данных

```text
node web-ais/scripts/test-program-site-generator.js
node web-ais/scripts/test-program-site-certificates.js
php web-ais/scripts/test-program-site-wordpress.php
node web-ais/scripts/test-program-site-sync.js
node web-ais/scripts/test-program-site-prototype.js
php web-ais/scripts/test-program-site-sync.php
node web-ais/scripts/test-program-site-sync.js --serve
```

Последняя команда открывает изолированный loopback-стенд с тестовыми данными и подменёнными сетевыми вызовами; она не обращается к рабочим WordPress или общей базе.
