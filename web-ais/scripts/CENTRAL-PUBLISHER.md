# Публикация с любого компьютера

На выделенном компьютере действует задача Windows `AisDopobrCentralPublisher`.
Она проверяет `simakrss/ais_dopobr`, ветку `codex/harden-static-serving`, каждые
три минуты и после входа пользователя в Windows. GitHub Actions и отдельный
сетевой вход на компьютер не нужны. Компьютер должен быть включён, подключён
к интернету; пользователь, зарегистрировавший задачу, должен оставаться в системе.

Для выпуска с другого компьютера:

1. Внести изменения и выполнить проверки.
2. Повысить `APPLICATION_RELEASE.version` в `web-ais/app.js`, обновить историю
   версии и идентификатор сборки в `index.html` и `auth-bootstrap.js`.
3. Сделать коммит и отправить его в `codex/harden-static-serving`.

Публикуется только новая версия из этой ветки. Обычные коммиты без повышения
версии ничего не публикуют. Рабочие папки разработчиков и данные АИС не используются
как каталог сборки: задача работает в отдельном `central-checkout`.

Пакет подписывается существующим ключом через `deploy-lms.ps1`. Неизменившийся
установщик повторно используется только при действительной Authenticode-подписи,
ожидаемом сертификате, отметке времени и совпадении с текущим исходным содержимым.
Каждая версия получает новый подписанный пакет и ZIP для установки.

При изменении установщика или компонентов Windows, требующих новой подписи,
задача останавливается **до публикации** с состоянием `needs-signature`.
Выполните обычную публикацию на выделенном компьютере и введите PIN в окне
сертификата. После этого автоматические выпуски продолжатся. PIN не сохраняется,
проверки подписи не отключаются, ключи не копируются на компьютеры разработчиков.

Состояние: `%LOCALAPPDATA%\AisDopobrPublisher\central-publisher\status.json`.
Настройки в соседнем `config.json` содержат только пути и название ветки.
FTP-профиль читается исключительно штатным `deploy-lms.ps1` из существующего ярлыка.
Пароли и содержимое ключей в эти файлы и журналы не записываются.

После публикации проверяются манифест, статические файлы и здоровье сайта.
Локальной АИС отправляется обычный запрос обновления. Сохранение открытых карточек
и завершение операций остаются обязательными; задача не принуждает перезапуск.
На последующих проверках сверяются локальная версия, все файлы пакета,
статические файлы по HTTP и здоровье сервера. До завершения показывается
`waiting-local`, после проверки — `idle` с `localVerified: true`.

Управление задачей:

```powershell
Start-ScheduledTask -TaskName AisDopobrCentralPublisher
Disable-ScheduledTask -TaskName AisDopobrCentralPublisher
Enable-ScheduledTask -TaskName AisDopobrCentralPublisher
```

Для переноса центра публикации используйте `register-central-publisher.ps1`
после подготовки отдельного checkout и существующих ключей. Не запускайте
два центра публикации одновременно.
