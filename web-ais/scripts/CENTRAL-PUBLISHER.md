# Публикация с любого компьютера

На выделенном компьютере действует задача Windows `AisDopobrCentralPublisher`.
Она запускается через минуту после загрузки Windows и проверяет
`simakrss/ais_dopobr`, ветку `codex/harden-static-serving`, каждые три минуты.
Вход пользователя в Windows не требуется. GitHub Actions и отдельный сетевой
вход на компьютер не нужны. Компьютер должен быть включён и подключён к интернету.
Если сеть ещё не готова, планировщик откладывает запуск; последующие проверки
повторяются по расписанию.

Задача использует фоновый сеанс S4U от учётной записи владельца сертификата
с ограниченными правами. Пароль Windows не сохраняется. GitHub читается анонимно
из публичного репозитория; ключ пакетов и FTP-профиль остаются на этом компьютере.
Вместо подключённого диска `Y:` используется физический путь на `D:`, поэтому
задаче не нужны вход пользователя, подключение сетевых дисков или запуск Яндекс Диска.
Файлы должны быть доступны на локальном диске, а не только в облаке.

Для выпуска с другого компьютера:

1. Внести изменения и выполнить проверки.
2. Повысить `APPLICATION_RELEASE.version` в `web-ais/app.js`, обновить историю
   версии и идентификатор сборки в `index.html` и `auth-bootstrap.js`.
3. Сделать коммит и отправить его в `codex/harden-static-serving`.

Публикуется только новая версия из этой ветки. Обычные коммиты без повышения
версии ничего не публикуют. Рабочие папки разработчиков и данные АИС не используются
как каталог сборки: задача работает в отдельном `central-checkout`.

Пакет подписывается существующим ключом через `deploy-lms.ps1`. Неизменившийся
установщик повторно используется только при действительной Authenticode-подписи,
ожидаемом сертификате, отметке времени и совпадении с текущим исходным содержимым.
Каждая версия получает новый подписанный пакет и ZIP для установки.

При изменении установщика или компонентов Windows, требующих новой подписи,
задача останавливается **до публикации** с состоянием `needs-signature`.
Выполните обычную публикацию на выделенном компьютере и введите PIN в окне
сертификата. После этого автоматические выпуски продолжатся. PIN не сохраняется,
проверки подписи не отключаются, ключи не копируются на компьютеры разработчиков.

Состояние: `%LOCALAPPDATA%\AisDopobrPublisher\central-publisher\status.json`.
Настройки в соседнем `config.json` содержат только пути и название ветки.
FTP-профиль читается исключительно штатным `deploy-lms.ps1` из существующего ярлыка.
Пароли и содержимое ключей в эти файлы и журналы не записываются.

После публикации проверяются манифест, статические файлы и здоровье сайта.
Локальной АИС отправляется обычный запрос обновления. Сохранение открытых карточек
и завершение операций остаются обязательными; задача не принуждает перезапуск.
На последующих проверках сверяются локальная версия, все файлы пакета,
статические файлы по HTTP и здоровье сервера. До завершения показывается
`waiting-local`, после проверки — `idle` с `localVerified: true`.

Управление задачей:

```powershell
Start-ScheduledTask -TaskName AisDopobrCentralPublisher
Disable-ScheduledTask -TaskName AisDopobrCentralPublisher
Enable-ScheduledTask -TaskName AisDopobrCentralPublisher
```

Для переноса или повторной настройки центра публикации используйте
`register-central-publisher.ps1 -AtStartup` после подготовки отдельного checkout
и существующих ключей. Регистрацию выполняют один раз от администратора;
сама задача остаётся с ограниченными правами. Не запускайте два центра
публикации одновременно. Перед повторной регистрацией дождитесь завершения
текущей публикации и отключите задачу на время настройки.

Указывайте физические локальные пути: сетевые диски, подключённые в обычном
пользовательском сеансе, могут отсутствовать уже в окне администратора.
Пути UNC к собственным общим папкам преобразуются в локальные; пути к другому
серверу и EFS-зашифрованным файлам для этого режима не принимаются.

Регистрация сначала проверяет конфигурацию, затем создаёт временную задачу
в фоновом сеансе 0: проверяет чтение GitHub, подпись манифеста, пробную подпись
существующим ключом пакетов, пригодность подписанного установщика и доступ
к FTP через штатный `deploy-lms.ps1 -ValidateProfileConnection`. Проверка
не публикует файлы. Только после её успеха заменяется основная задача.
Результат находится в `background-verification.json` рядом с `config.json`;
`sessionId: 0`, `interactive: false` и успешные проверки подтверждают
доступность зависимостей вне пользовательского рабочего стола.

Если настройки читаются из JSON в Windows PowerShell 5.1, обязательно используйте
`Get-Content -Raw -Encoding UTF8`, чтобы сохранить кириллицу в путях.
