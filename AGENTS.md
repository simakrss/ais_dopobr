# Инструкции проекта

## Обязательное завершение каждой правки

- После каждого изменения кода, конфигурации или содержимого выполни релевантные проверки, создай обычный коммит и отправь текущую ветку в настроенный upstream GitHub. Не используй force-push.
- Перед добавлением файлов проверь `git status` и включай в коммит только файлы текущей задачи. Не используй `git add -A`; не затрагивай чужие изменения, резервные копии, `tmp`, `storage` и нумерованные дубликаты.
- После успешного push опубликуй все изменённые файлы, относящиеся к сайту, штатным сценарием `web-ais/scripts/deploy-lms.ps1 -RelativePath ...`.
- После публикации проверь успешный статус загрузки и размеры файлов, доступность `https://edu-plus.ru/lms/` (HTTP 200), ответ `https://edu-plus.ru/lms/api/health` (`ok: true`) и по возможности совпадение хеша или размера изменённых статических файлов.
- Если изменены только инструкции, документация или тесты и публикуемых файлов сайта нет, всё равно выполни commit/push в GitHub и явно сообщи, что публикация сайта не требовалась. Не загружай несвязанные файлы.
- Если push или публикация не завершились, не объявляй задачу полностью выполненной: сообщи точный этап и ошибку.
- В итоговом ответе укажи хеш коммита, ветку, опубликованные файлы и результаты проверок.

## Секреты публикации

- FTP-профиль хранится только в локальном ярлыке `lms на vh458.timeweb.ru.lnk` в корне репозитория. Используй его только через `web-ais/scripts/deploy-lms.ps1`.
- Никогда не выводи, не декодируй, не копируй и не сохраняй логин, пароль или полный FTP URL из ярлыка в исходниках, Git, сообщениях, журналах или аргументах командной строки.
- Ярлык должен оставаться локальным и исключённым из Git правилом `.gitignore` `*.lnk`.
