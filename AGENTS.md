# Инструкции проекта

## Единый интерфейс

- Во всех новых и изменяемых окнах используй стандартные элементы АИС: `modal`, `modal-head`, `modal-actions`, `form-grid`, соответствующие стили полей карточек и кнопки `primary-button`, `ghost-button`, `icon-button`. Не оставляй поля и кнопки с браузерным оформлением по умолчанию. Проверяй, что окно помещается на узком экране.

## Обязательное завершение каждой правки

- После каждого изменения кода, конфигурации или содержимого выполни релевантные проверки, создай обычный коммит и отправь текущую ветку в настроенный upstream GitHub. Не используй force-push.
- Перед добавлением файлов проверь `git status` и включай в коммит только файлы текущей задачи. Не используй `git add -A`; не затрагивай чужие изменения, резервные копии, `tmp`, `storage` и нумерованные дубликаты.
- После успешного push опубликуй все изменённые файлы, относящиеся к сайту, штатным сценарием `web-ais/scripts/deploy-lms.ps1 -RelativePath ...`: через настроенную центральную задачу (см. ниже) или вручную при её остановке. Не запускай эти способы одновременно.
- После публикации проверь успешный статус загрузки и размеры файлов, доступность `https://edu-plus.ru/lms/` (HTTP 200), ответ `https://edu-plus.ru/lms/api/health` (`ok: true`) и по возможности совпадение хеша или размера изменённых статических файлов.
- При каждом обновлении обновляй и облачную, и рабочую локальную версию. После публикации подписанного пакета дождись его штатной установки в запущенной локальной АИС; проверь версию через локальный `/api/local-update/status`, здоровье `/api/health` и хеши изменённых файлов, полученных по HTTP. Путь рабочей копии определяй по запущенному серверу, а не по папке разработки. Не обходи ожидание сохранения карточек и завершения операций, не подменяй готовность окон. Если локальная установка заблокирована или сервер недоступен, явно сообщи об этом; одной публикации пакета недостаточно, чтобы считать локальную копию обновлённой.
- Если изменены только инструкции, документация или тесты и публикуемых файлов сайта нет, всё равно выполни commit/push в GitHub и явно сообщи, что публикация сайта не требовалась. Не загружай несвязанные файлы.
- Если push или публикация не завершились, не объявляй задачу полностью выполненной: сообщи точный этап и ошибку.
- В итоговом ответе укажи хеш коммита, ветку, опубликованные файлы и результаты проверок.

## Центральная публикация через GitHub

- На компьютере с действующим сертификатом настроена задача `AisDopobrCentralPublisher`: запускается через минуту после загрузки Windows без входа пользователя и каждые три минуты проверяет `origin/codex/harden-static-serving`. Задача работает от учётной записи владельца сертификата в фоновом сеансе S4U с ограниченными правами. Новый номер `APPLICATION_RELEASE.version` после push запускает штатный `deploy-lms.ps1` из отдельного `central-checkout`. Коммиты без повышения версии не публикуются.
- При работе с другого компьютера используй этот механизм вместо переноса ключей и FTP-профиля. После push дождись нового подписанного манифеста и проверь сайт. Не запускай одновременно вторую публикацию той же версии. Ручная публикация на выделенном компьютере остаётся возможной при остановленной центральной задаче.
- Установщик повторно используется только после проверки подписи, сертификата, отметки времени и совпадения исходного содержимого. Если установщик или подписываемые компоненты Windows изменились, автоматическая публикация останавливается до загрузки файлов с `needs-signature`; PIN вводится пользователем только в окне сертификата.
- Состояние задачи: `%LOCALAPPDATA%\AisDopobrPublisher\central-publisher\status.json`; `localVerified: true` подтверждает локальную установку по версии, файлам и HTTP. Если этот файл недоступен с другого компьютера, отдельно укажи, что локальная установка не проверена; не выдавай публикацию сайта за подтверждение всех установок.
- Настройка и порядок выпуска описаны в `web-ais/scripts/CENTRAL-PUBLISHER.md`. Компьютер публикации должен быть включён и подключён к интернету; вход пользователя в Windows не требуется. Все рабочие пути задачи должны вести на физические локальные диски, без подключённых сетевых дисков. Регистрация `-AtStartup` требует однократного запуска от администратора и проверяет зависимости в отдельном фоновом сеансе до замены задачи. PIN и пароль Windows не хранить, проверки подписей не отключать.

## Секреты публикации

- FTP-профиль хранится только в локальном ярлыке `lms на vh458.timeweb.ru.lnk` в корне репозитория. Используй его только через `web-ais/scripts/deploy-lms.ps1`.
- Никогда не выводи, не декодируй, не копируй и не сохраняй логин, пароль или полный FTP URL из ярлыка в исходниках, Git, сообщениях, журналах или аргументах командной строки.
- Ярлык должен оставаться локальным и исключённым из Git правилом `.gitignore` `*.lnk`.
